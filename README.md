# 佛来运转 H5 核心闭环

这是从旧 App/小程序模板中独立出来的低成本 H5 第一版，只保留真实业务闭环：项目介绍、终端用户发布需求、需求查询、项目详情、我的待完成/已完成、相册查看、接单员任务台、确认接单、拍照/视频上传、流转、完成、后台管理、R2 图片/视频存储、D1 数据库。

## 已按介绍资料补齐的终端用户功能

- 手机号登记和昵称设置：保存在本机浏览器，方便 H5 低成本使用。
- 发布需求必须填写渠道码：对应原小程序里“接单员渠道码填错就看不到订单”的规则。
- 发布需求支持一次添加多个项目和数量。
- 发布信息包含姓名、手机号、生日、年龄、属相、性别、备注。
- 提交成功返回需求编号和查询码。
- 需求查询使用“需求编号 + 查询码”，避免公开暴露姓名、生日、照片视频。
- 我的需求分为待完成和已完成。
- 已完成需求提供相册入口；正式部署后媒体文件存入 R2。
- 接单员任务台支持确认接单、流转、拍照/视频选择、完成。

## 第一版边界

- 不迁移旧商城、购物车、优惠券、积分、钱包、分销、售后物流、App 更新、小程序专属搜索/收藏入口。
- 手机短信验证码、微信登录、在线支付先不做；第一版以低成本 H5 闭环跑通真实流程。
- 公开详情和媒体访问必须带查询码。
- 后台写操作和上传接口必须配置 `ADMIN_TOKEN`，没有 Token 时拒绝后台操作。
- D1 负责结构数据，R2 负责照片和视频文件。

## 本地查看

直接打开 `index.html` 可以看 H5 演示界面；没有 D1/R2 时，前端使用浏览器本地演示数据。

## 部署准备

1. 创建 D1 数据库并替换 `wrangler.toml` 里的 `database_id`。
2. 创建 R2 bucket：`folai-prayer-media`。
3. 设置 Pages 变量/密钥：`ADMIN_TOKEN`。
4. 执行 `migrations/0001_core_schema.sql`。
5. 部署 Cloudflare Pages，保留 `functions/api` 目录。
